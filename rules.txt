
✅ PHASE 1 — Project Initialization (Instructions Only)**

1) Create Next.js Project (JavaScript Only)**

* Create a new Next.js project
* Use **App Router**
* Use **JavaScript only** (no TypeScript)
* Do **not** include Tailwind during creation (install manually later)

---

2) Install Required UI & Animation Libraries**

* Install **Tailwind CSS**, **PostCSS**, **Autoprefixer**
* Install **Framer Motion**
* Install **GSAP**
* Install **AutoAnimate**

---

3) Configure Tailwind CSS**

* Generate Tailwind configuration files
* Add Tailwind paths for `app`, `components`, etc.
* Add Tailwind base/utilities/components inside `globals.css`

---

4) Add Arabic RTL Support**

* Install **tailwindcss-rtl** plugin
* Enable RTL plugin inside Tailwind config
* Set the website direction to RTL when Arabic is active

---

5) Add Multilanguage Support (Arabic + English)**

* Install **next-intl**
* Create an **i18n folder** containing translation files:

  * `ar.json`
  * `en.json`
* Create a locale-based route:

  * `/app/[locale]/layout.js`
* Set `<html>` attributes so:

  * Arabic → `dir="rtl"`
  * English → `dir="ltr"`

---

6) Set Up Folder Structure**

Create these folders (no code, just structure):

* **app/**

  * `[locale]/`
  * `admin/`
  * `login/`
  * `api/`
* **components/**

  * `shared/`
  * `admin/`
  * `animations/`
* **hooks/**
* **lib/**
* **i18n/**
* **styles/**

---

7) Animation Setup Preparation**

Prepare files for:

* Framer Motion wrapper
* GSAP animation hooks
* AutoAnimate reusable hook

(No implementation needed — just create placeholders)

---

8) Phase Validation**

Before moving to Phase 2, ensure:

* Project runs successfully
* Tailwind is working
* RTL is working properly
* Multi-language routing works
* Animation libraries are installed
* Folder structure is ready

✅ PHASE 2 — (FrontEnd :: Admin side )

### **1️⃣ Login Page Flow**

* **Initial State**

  * Centered `LoginCard` with `LoginForm` (email + password inputs)
  * Submit button (`LoginActions`) in **idle state**
  * Full-screen layout, no sidebar or navbar

* **On Submit**

  * Button switches to **loading spinner**
  * Disable form inputs to prevent multiple clicks
  * Trigger `useAdminAuth.login()` hook

* **API Response Handling**

  * **Success**:

    * Animate button to **success check mark**
    * Optional bounce/scale effect for feedback
    * Redirect to `/admin/dashboard`
  * **Error**:

    * Button shakes / highlight red
    * Returns to idle state
    * Show error message below form

* **Animations**

  * Framer Motion → button transitions, check mark animation
  * GSAP → optional shake animation on error
  * AutoAnimate → smooth form field transitions (if adding/removing fields later)

---

### **2️⃣ Dashboard Initial Load**

* **Sidebar**

  * Appears immediately after login
  * **No tab selected by default** → clean, fresh look
  * Items fade in sequentially using Framer Motion `staggerChildren`
  * Hover effect active only on mouse over
  * First click → item becomes active

* **Navbar**

  * Shows profile/logout options
  * No interaction selected initially

* **Content Area**

  * Placeholder welcome message or dashboard cards (e.g., "Welcome, Admin!" / quick stats)
  * Uses `CenterBox` + Tailwind utilities for clean spacing
  * Avoids empty page feel

* **Loading & Empty States**

  * `LoadingState.jsx` → shows spinner while fetching dashboard data
  * `EmptyState.jsx` → shown if no data exists
  * Both reusable for future CRUD pages (Products, Orders, etc.)

---

### **3️⃣ Navigation Flow**

* `/admin` → Login page
* Successful login → redirect `/admin/dashboard`
* Middleware protects `/admin/dashboard`

  * If token missing → redirect back to `/admin`

---

### **4️⃣ Button Animation States (LoginActions.jsx)**

* `idle` → default button text

* `loading` → spinner animation while API call is in progress

* `success` → check mark animation if login succeeds

* `error` → shake + revert to `idle` if login fails

* Controlled by `useAdminAuth` hook → updates state based on API response

---

### **5️⃣ UX Polish**

* Smooth fade-in for sidebar items
* Soft hover effects for interactive elements
* Welcome message or stats cards to avoid empty dashboard content

✅ PHASE 2 — (Backend :: Admin side )

## **1️⃣ Service Layer (`adminAuth.service.js`)**

* **Purpose**: abstraction layer for all API calls related to admin authentication.
* **Login function**:

  * `login(email, password)` → POST request to `/auth/login` endpoint
  * Returns **promise** with JSON response:

    * Success → `{ token, adminData }`
    * Error → `{ errorMessage }`
* Handles request errors (network, server errors)
* Uses global `http.js` (Axios/fetch wrapper) for base URL, headers

---

## **2️⃣ Hook Layer (`useAdminAuth.js`)**

* **Purpose**: manage login logic, state, and token storage

* **State management**:

  * `status` → `"idle" | "loading" | "success" | "error"`
  * `errorMessage` → string from API response

* **Login flow**:

  1. Set `status` to `"loading"`
  2. Call `adminAuth.service.login(email, password)`
  3. On success:

     * Store token via `utils/storage.js` (localStorage)
     * Set `status` to `"success"`
     * Return success response for UI to redirect
  4. On error:

     * Set `status` to `"error"`
     * Store `errorMessage` for UI display
     * Return failure response

* **Hook API for components**:

  ```js
  const { login, status, errorMessage } = useAdminAuth();
  login(email, password); // async call
  ```

---

## **3️⃣ Component Integration (`LoginActions.jsx`)**

* **Purpose**: show animated button states in response to hook

* **State mapping**:

  * `idle` → normal "Login" text
  * `loading` → spinner
  * `success` → check mark animation
  * `error` → shake + revert to idle

* **Flow**:

  1. User clicks button → calls `login(email, password)` from hook
  2. Button switches to `loading`
  3. Hook updates `status` based on API response
  4. Button animation reacts to `status` changes:

     * `success` → check mark + redirect dashboard
     * `error` → shake + revert text to "Login"

---

## **4️⃣ Storage / Token Handling (`utils/storage.js`)**

* **Purpose**: abstract localStorage/cookie operations for authentication

* Functions:

  * `setToken(token)` → store JWT
  * `getToken()` → retrieve token
  * `removeToken()` → delete token on logout or error

* **Integration**:

  * `useAdminAuth.js` calls `setToken` on successful login
  * `middleware.js` uses `getToken` to protect `/admin/dashboard`

---

## **5️⃣ Middleware (`middleware.js`)**

* **Purpose**: protect dashboard routes

* **Flow**:

  1. Check token existence via `storage.getToken()`
  2. If token missing → redirect to `/admin`
  3. If token present → allow access to `/admin/dashboard`

* **Optional**: can add token validation via API ping

---

## **6️⃣ Error Handling & UX Integration**

* **API errors**:

  * Network error → `status = error`, display generic message
  * Invalid credentials → `status = error`, display specific message
* **UI connection**:

  * `LoginActions.jsx` observes `status`
  * Animations update dynamically without page reload
